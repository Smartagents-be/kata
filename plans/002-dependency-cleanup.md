## Why this matters

`shadcn` is the component-scaffolding **CLI**, but it sits in `dependencies`, so
the production dependency tree pulls in Babel, `ts-morph`, and
`@modelcontextprotocol/sdk` (an MCP server SDK with an HTTP server behind it).
Three of the five advisories `npm audit` reports — including the only ones in
`npm audit --omit=dev` — arrive solely through that subtree, so the
production-only audit can never be used as a CI gate. Separately, `react-router-dom`
has a patch (7.18.2) inside the existing `^7.18.1` range that clears a high
advisory (the advisory itself is RSC-mode-only and unreachable in this
BrowserRouter SPA — the point of taking it is a clean audit, not exposure).

## Current state

- `front/package.json` `dependencies` includes `"shadcn": "^4.13.1"`. No file
  under `front/src` imports it as a module (`grep -rn "from ['\"]shadcn"` → 0
  hits), but it **is** consumed at build time by one CSS import:

  ```css
  /* front/src/index.css:1-3 */
  @import "tailwindcss";
  @import "tw-animate-css";
  @import "shadcn/tailwind.css";
  ```

  Vite resolves that from `node_modules/shadcn/dist/tailwind.css` regardless of
  which dependency block the package sits in, so moving it to
  `devDependencies` changes nothing about the build. Do **not** remove the
  package or the `@import`.
- `npm audit` (in `front/`) reports 5 advisories: react-router (high, RSC-mode
  CSRF, unreachable here), `brace-expansion` (high, via
  `shadcn → ts-morph → minimatch`), and the `@hono/node-server` /
  `@modelcontextprotocol/sdk` pair (moderate, via `shadcn`).
- `npm outdated` shows `react-router-dom` 7.18.1 → 7.18.2 available in-range.
- Repo convention: `components.json` points the shadcn CLI at
  `@/shared/components/ui`; the CLI keeps being invoked via
  `npx shadcn@latest add …`, which works from devDependencies.

## Steps

### Step 1: Move `shadcn` between dependency blocks

In `front/package.json`, delete `"shadcn": "^4.13.1"` from `dependencies` and
add it to `devDependencies` (keep both blocks alphabetically sorted, matching
the current file). Run `npm install`.

**Verify**: `node -e "const p=require('./package.json'); console.log(!!p.devDependencies.shadcn && !p.dependencies.shadcn)"` → `true`

### Step 2: Take the in-range updates

```bash
npm update
```

**Verify**: `npm ls react-router-dom` → version ≥ 7.18.2, still 7.x.
`git diff package.json` shows no semver-range changes other than Step 1's move
(npm update touches only the lockfile for in-range bumps).

### Step 3: Prove the build is unchanged

```bash
npm run build && npm run lint
```

**Verify**: both exit 0. The build output lists CSS assets — no missing-import
error for `shadcn/tailwind.css`.

### Step 4: Confirm the audit position

```bash
npm audit --omit=dev
npm audit
```

**Verify**: `--omit=dev` reports **0** vulnerabilities. Record the full-audit
count in your report (expected: at most the dev-only remainder).
