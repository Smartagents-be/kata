Everything earlier in this conversation. Your previous turns, the agent's replies, the system messages the harness slipped in, every tool call it made. And usually the bulk of it: the tool results. A file it opened, a test run it executed, a stack trace you pasted.

Time sets this layer apart from the other 3. A prompt is written for 1 turn, the harness loads the same material into every request, a tool result arrives the moment something runs. The session is the only layer with a history behind it, because it is the history.

So the other layers end up here too. A page the agent fetched an hour ago can still go out with every request, until the harness clears or summarises it.

You hardly had to write any of it yourself

Count what is in there and your own words barely register. You type a sentence, and the agent opens 2 files, runs the test suite and pastes the output back. Your sentence is 14 tokens. Everything around it is 5,000.

2 bars in that stack are yours, and they are the short ones. Everything else landed there without you typing a word. So this is the layer you author least and are still responsible for. It fills itself up, mostly with output nobody read, while you are busy thinking about something else.

You can change the session after the work: remove history with a rewind (press Esc 2 times on an empty prompt), summarise it with compaction, or clear it for a fresh task. Preserve any decisions you still need in a durable file first.

The session sets your bill

What stays in the window is paid for again on every turn. Read 3 large files early and you keep paying for them until they are cleared or summarised.

Quick follow-up questions are cheap, because most of the window then comes from the cache. A new task belongs in a fresh window.

So ask everything you want to know about a piece of code while it is in front of you But not forever: the same session that makes your second question cheap makes your 50th expensive and vague.

Automatic or manual compaction

Compaction replaces the conversation so far with a summary. The harness does it on its own when the window fills up, or you start it yourself.

  • Automatic: the harness summarises when the window nears its limit, sometimes in the middle of a task.
  • Manual: /compact with what to keep, such as /compact keep the failing tests. Moving to something unrelated? Clear instead.

A summary loses detail. Ask the agent what it still knows before you build on it.

Compaction costs tokens too: the model reads the conversation and writes the summary. /clear is free, but the next session reads everything again.

Claude Code compacts when the window is about full, and /autocompact sets that point lower, anywhere from 100K to 1M tokens, so compaction comes earlier. It still picks the moment. You only move it.

Copilot CLI starts early on its own: from about 80% of the window it compacts in the background, while you keep working. You cannot change that threshold.

The window is not your memory

Anything that has to survive a clear belongs somewhere other than the transcript. The code on disk survives. A plan written to a file survives. CLAUDE.md is read again at the start of every session, which is why a standing instruction goes there and not in a message you sent an hour ago.

When a problem is closed, clear, and start the next session with what survived: the code on disk, which is now correct, plus a sentence about where you are.

What separates people who get good work out of an agent from people who fight it is mostly this: knowing what is in the window right now, and being willing to throw it away.
