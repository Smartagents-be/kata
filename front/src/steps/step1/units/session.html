Everything earlier in this conversation. Your previous turns, the agent's replies, the system messages the harness slipped in, every tool call it made. And usually the bulk of it: the tool results. A file it opened, a test run it executed, a stack trace you pasted.

What sets this layer apart from the other three is time. A prompt is written for one turn, the harness loads the same material into every request, a tool result arrives the moment something runs. The session is the only layer with a history behind it, because it is the history.

Which means the other layers end up here too. That documentation page the agent pulled off the web was a tool result for exactly one turn. After that it is a paragraph in the transcript, going out again with every message you send. The session is where everything settles.

You wrote almost none of it

Count what is in there and your own words barely register. You type a sentence, and the agent opens two files, runs the test suite and pastes the output back. Your sentence is fourteen tokens. Everything around it is five thousand.

Two bars in that stack are yours, and they are the short ones. Everything else landed there without you typing a word. So this is the layer you author least and are still responsible for. It fills itself up, mostly with output nobody read, while you were busy thinking about something else.

It is also the only layer you can do anything about afterwards. You cannot shorten the harness's system prompt and you cannot un-send a turn. You can throw the session away. That is the whole lever.

Sessions are where the money goes

The context unit already did this sum: the whole session goes back every turn, so its size is your price per message. Read three large files early and you keep paying for them on every question you ask afterwards, whether or not they still matter.

A long session cuts both ways. Once Catalog is in the window, a second and a third question about it cost almost nothing extra. Harnesses cache the front of the pile, so what has not changed since the last turn is billed at a fraction. The harness unit prices that. Adding to a session is cheap. Rebuilding one is not.

So ask everything you want to know about a piece of code while it is in front of you But not forever: the same session that makes your second question cheap makes your fiftieth expensive and vague.

Compaction picks the moment, or you do

When the pile stops fitting, the harness compacts it. A model reads the transcript, writes a summary, and the summary is what you carry on with. Detail goes first. And it fires exactly when the work got long and complicated, so it lands in the middle of the hardest thing you did all day.

/clear is the same loss on your own terms. You choose the seam, you decide what is worth carrying across, and you open the next session with it. Both throw work away. Only one lets you say what stays.

The window is not your memory

Anything that has to survive a clear belongs somewhere other than the transcript. The code on disk survives. A plan written to a file survives. CLAUDE.md is read again at the start of every session, which is why a standing instruction goes there and not in a message you sent an hour ago.

Careful session management is most of what separates people who get good work out of an agent from people who fight it. Not a bigger model, not a longer prompt. Knowing what is in the window right now, and being willing to throw it away.
