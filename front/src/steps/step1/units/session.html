Everything earlier in this conversation. Your previous turns, the agent's replies, the system messages the harness slipped in, every tool call it made. And usually the bulk of it: the tool results. A file it opened, a test run it executed, a stack trace you pasted.

Time sets this layer apart from the other 3. A prompt is written for 1 turn, the harness loads the same material into every request, a tool result arrives the moment something runs. The session is the only layer with a history behind it, because it is the history.

So the other layers end up here too. A page the agent fetched an hour ago can still go out with every request, until the harness clears or summarises it.

You hardly had to write any of it yourself

Count what is in there and your own words barely register. You type a sentence, and the agent opens 2 files, runs the test suite and pastes the output back. Your sentence is 14 tokens. Everything around it is 5,000.

2 bars in that stack are yours, and they are the short ones. Everything else landed there without you typing a word. So this is the layer you author least and are still responsible for. It fills itself up, mostly with output nobody read, while you are busy thinking about something else.

You can change the session after the work: remove history with a rewind (press Esc 2 times on an empty prompt), summarise it with compaction, or clear it for a fresh task.

The session sets your bill

The context unit showed that everything in the context is sent again with every message. Read 3 large files early and you keep paying for them until they are cleared or summarised.

Quick follow-up questions are cheap, because most of the context then comes from the cache.

So ask everything you want to know about a piece of code while it is in front of you But not forever: the same session that makes your second question cheap makes your 50th expensive and vague.

Entropy

A long session piles up failed attempts, errors and old versions of files. The harness does not reliably clear them out.

That is entropy: disorder in the context rises with every turn unless somebody spends energy pushing it back down. You see it when the agent starts contradicting itself, re-proposes an idea you already rejected, or edits a file back to a version you moved past an hour ago.

Clear when a problem is closed Start the next session with what survived: the code on disk, which is now correct, plus 1 sentence about where you are.

Compaction and /clear

Compaction replaces the conversation so far with a summary, and you go on in the same session. /clear starts a new session: the conversation is gone, and nothing is summarised.

  • Automatic: the harness summarises when the context nears its limit, sometimes in the middle of a task.
  • Manual: /compact with what to keep, such as /compact keep the failing tests.

Compact when you are in the middle of a task and want to go on. Clear when you start on something else.

Compaction costs tokens: the model reads the conversation and writes the summary. /clear costs nothing, but whatever the next task needs has to be read in again.

Claude Code compacts when the context is about full, and /autocompact sets that point lower, anywhere from 100K to 1M tokens, so compaction comes earlier. It still picks the moment. You only move it.

Copilot CLI starts early on its own: from about 80% of the context it compacts in the background, while you keep working. You cannot change that threshold.

Amnesia and context fatigue

After compaction, the summary is what stays. The constraint you gave at the start is now 1 line in it, or it did not make the cut at all.

Then the agent forgets a decision from earlier, asks a question you already answered, or re-reads a file it read 20 minutes ago. This is context fatigue. The model did not get tired and it did not get dumber. The evidence left the room.

Ask the agent what it still knows before you build on a summary. Better still, cut each task small enough that it finishes before the summarising begins.

The context is not your memory

Anything that has to survive a clear belongs somewhere other than the transcript. The code on disk survives. A plan written to a file survives. CLAUDE.md is read again at the start of every session and after compaction, which is why a standing instruction goes there and not in a message you sent an hour ago. Keep that file short: Anthropic advises under 200 lines, because a longer file costs more context and is followed less well.

What separates people who get good work out of an agent from people who fight it is mostly this: knowing what is in the context right now, and being willing to throw it away.
