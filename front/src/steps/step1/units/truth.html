The same question can have more than 1 true answer, and which one you get depends on where the agent looked. Part of what it knows was fixed on the day its training stopped. None of it was ever about your company. Not your repository, and not the version you are on.

Everything else has to reach it somehow. You put it in the context yourself, or the agent goes and finds it with a tool. Ask which version of Spring Boot this project builds on and a current agent opens pom.xml on its own. What it does not look up is what it thinks it already knows: how an API works, which dependency a feature needs, what changed in the latest release. That comes straight from training.

So which of the 3 is the truth? The one it went and discovered, the one you handed it, or the one it already had. All 3 arrive in the same voice.

The cutoff

Training stopped on a date, and providers publish that date for every model. Whatever was published after it is not something the model knows a little less well. It has never seen it. A framework released last spring, a library that threw out its whole configuration format between one minor version and the next: none of that is in there.

The answer still arrives. It describes the version line before yours, in the same level tone as everything else. It is out of date rather than wrong, and that is harder to spot. This is the half of the model that ages while you are not looking.

Grounding

Put the evidence in the context and the answer changes source. The pom.xml on disk, the release notes fetched off the web, the output of a command that ran a second ago: once any of it is in the context, the model is reading rather than remembering. That is a grounded answer, and it is the one you want for anything with a fact behind it.

Only the context changed. How a page gets in there is the unit on the agentic loop. Your part is asking for it, because an agent that feels sure does not ask itself. "Which dependency does @WebMvcTest need" gets the answer it remembers. "Read the Spring Boot 4.1 docs on test slices, then tell me which dependency @WebMvcTest needs" gets the one in the docs.

The same goes for anything else outside your project: an option that changed last month, a price, a limit. Send the agent to the vendor's own documentation before it answers.

Proof

Grounded is still not proved, and that is the answer to the question up top: the source is not the same thing as the check. The agent read a file and told you what it says, and you are taking its word for the reading. Run whatever can be run: mvn test, a curl at the endpoint, 1 line of jshell. An answer with a command behind it is one you can check yourself.

Ask for the check rather than the conclusion, then. Not "does this handle an empty list" but a test that goes red on an empty list Reasoning about what the code does and running it are 2 different claims, and only one of them can fail in front of you.

Dependencies deserve the same check. Models invent package names that sound right, often the same ones every time, so attackers register exactly those names with malware inside. Check that a package exists, and that it is the one you meant, before you add it.

Hallucinations

With nothing in the context to read, the model answers anyway. Answering is what it does, and you have met it once already: the quiz back in the context unit asked why a confident answer about a UserService missed the class entirely. Ask which method on Catalog filters titles by author and you get findAllByAuthorOrdered, spelled exactly the way a Spring method is spelled, on a class that has no such method. Nothing was looked up, and nothing was deliberately made up. The next likely token landed where a fact should have been, and that is a hallucination.

2 of those were read and 1 was not, and the answer says the same thing about all 3. A hallucination is expensive because the model sounds the same whether it read your file or filled the gap. Training makes that worse: a confident guess scores better than "I do not know". So give the agent that way out, and ask it to say when it has not checked something. Then stop reading the tone and start asking where the answer came from. The workshop is that question 5 times over.
