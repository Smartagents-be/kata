An agent has no memory of its own. Everything it knows when it answers you was assembled a moment earlier, pulled together from a handful of separate sources and handed to the model as one block of text. That block is the context.

Claude Code can show your current context using the /context command. It prints the current context grouped by where the context came from.

A model is stateless

Between two messages an LLM keeps nothing. Not your last question, not the file it opened, not the decision the two of you reached. Every request starts from zero. What feels like a conversation is the entire transcript being sent again, from the top, every single time.

Sending that whole transcript again is not free. The longer you talk to an LLM, the bigger the tasks and the more of them stack up, the more every turn costs. Keep that in mind and clear the session often enough, especially when you switch to something unrelated. A fresh session keeps the model focused, even when it has to re-read a file to solve the problem in front of it.

And it is a statistic

It is also a statistical model rather than a reasoning database. It predicts the most likely continuation of the text it was given, using patterns from its training data. It holds no opinion about your codebase. What it holds is an average.

That is why context is the only lever you have. The model gets better at your task at exactly the moment you or the harness put your task in front of it. Give it nothing and it answers from the average of everything it ever read.

Relevant context does not only make an answer more correct. It raises the quality.

Bad context, bad answers

Missing context produces generic output. You recognise it instantly: the tutorial answer, the UserServiceImpl, the try-catch that swallows the exception. It is not wrong exactly. It is just answering a question nobody in your team asked.

Often that gap is recoverable, because the harness can go and get what it lacks. When reading is not enough, it interviews you instead.

Wrong context is the dangerous kind, because the model cannot tell that it is wrong. Paste a file that is three versions old and it builds on top of it without a second thought. Nothing in the window says "stale". Everything in the window reads as true.

And it slips in by accident more than you would think. Chase a bug through a long session and finally kill it: the fix lands in your code, but the whole hunt stays in the window. The broken version, the wrong turns, the diff you reverted, all still sitting there. Ask for the next thing without clearing and the model reads that dead code as live. It can decide your fix was the mistake, put the bug back, and the first you hear of it is the test going red again. That pile-up in the context is entropy.

Why this bites hardest in code

There is far more bad code on the internet than good code. Abandoned tutorials, answers from 2011, snippets that never ran in production, homework. A model trained on all of it has seen the thing you should not do thousands of times.

It cannot tell the two apart. "Good" and "bad" are not labels in the training data. Frequency is the only signal, so a vague question returns the statistical middle of everything ever written about the topic. That middle is mediocre code that happens to compile.

More context is not free

Every token in the window is paid for, on every turn, because the whole context goes back to the model with each message. A long session does not cost slightly more. It costs more per message, for the rest of the session.

So the goal is not maximum context. It is context that is small enough and good enough. The file that matters instead of the whole directory. Every extra token you throw in raises the cost.

Entropy

In an agentic session the context only grows, and a lot of what lands in it is noise. Failed attempts. A command that errored. The same file read at three different moments, in three different states. An approach you abandoned halfway. None of it is removed, and the model weighs all of it.

That is entropy: disorder in the window rises with every turn unless somebody spends energy pushing it back down. The symptoms are easy to recognise once you know them. The agent starts contradicting itself, re-proposes an idea you already rejected, or edits a file back to a version you moved past an hour ago.

This has a name of its own: lost in the middle. Nothing was deleted. The line that decides the answer is still sitting in the window, but so is everything else, and the model reads straight past it because it weighed that line as less important than the bulk around it.

Amnesia and context fatigue

Because the window is finite, something eventually has to give. Older material is compacted into a summary or drops out completely. The constraint you gave at the start is now one line in a summary, or it is simply gone.

Then the agent forgets a decision from earlier, asks a question you already answered, or re-reads a file it read twenty minutes ago. This is context fatigue, and it is worth being precise about what happened. The model did not get tired and it did not get dumber. The evidence left the room.

When the window is compacted, detail is the first thing to go. For an instruction that has to survive that, write it in CLAUDE.md, which is read at the start of every session. And keep the window from filling up in the first place: cut each task small enough that it finishes before the summarising begins.
