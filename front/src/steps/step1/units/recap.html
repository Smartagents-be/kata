The harness assembled the context for each answer. This step separated what fits in that context, the tokens processed across requests, and the evidence supporting the answer. Those quantities belong together, but they are not interchangeable.

What it costs, and what to do about it

  • Text is counted in tokens; density depends on the input and tokeniser. Paste the relevant part of a log .
  • Follow-ups process the retained context again, and reasoning is billed as output. Bundle related changes and check actual usage .
  • Even an unused tool can take up context if its description is loaded. Turn off the ones this task does not need .
  • Old assumptions can remain in the window despite their source labels. Check current files. Clear between unrelated tasks or use /compact; automatic and manual compaction both spend tokens .
  • Earlier answers and retrieved content in your session count as input for as long as they remain in the active context. Ask your follow-up questions while the relevant code is still available .
  • The harness supplies instructions and can cache a matching prefix. Check cache reads, writes and lifetime before estimating savings, and pick your model and effort at the start of a session .
  • Model choice changes the rates and capabilities available. Try a cheaper worker for a well-defined task and verify the result .
  • An answer sounds the same whether it read your file or filled the gap. Ask for the check rather than the conclusion: a test that goes red on an empty list is an answer you can check yourself, and so is a package you looked up before adding it .
  • Claude’s 5-hour allowance and weekly limits are separate from context capacity. Check the reported reset and remaining limits before scheduling a long run .
