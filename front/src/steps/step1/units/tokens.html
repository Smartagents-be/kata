Before anything reaches the model, your text is cut into chunks and every chunk is swapped for a number. Those chunks are tokens.

Text reaches a language model as tokens. They measure how much text fits and how much is processed. Models that accept images or audio also have representations for those inputs. A token count is not a word count or a character count.

For ordinary English, roughly 4 to 6 characters go into 1 token, so a page of text comes to a few hundred tokens.

Reading

Models do not process text as separate words

A tokeniser uses a fixed vocabulary and segmentation rules learned from text. Common words often stay whole; other words split into smaller pieces. The BPE tokeniser in this example applies ranked merges, rather than always choosing the longest known piece. Different tokenisers draw different boundaries.

Attention

In He deposits his money at the bank, bank could mean a river bank or an institution that handles money. The words deposits and money help identify the right meaning. The model weighs information from other tokens to make such connections. That weighing is called attention.

Every token gets 3 vectors: a query, a key and a value. They serve different roles. When a token seeks information from other tokens, its query expresses what it needs. When other tokens attend to this token, its key expresses what it offers. Its value contains the information it actually contributes.

For bank, the model compares its query with the keys of every earlier token and itself. It calculates their dot product: multiply the numbers at corresponding positions in the 2 vectors, then add the results. Each comparison produces a score.

The scores are converted into weights that add up to 100%. The higher the score, the more the corresponding value contributes. The model multiplies each value-vector by its weight and adds the vectors together, position by position. That lets information from deposits and money weigh heavily in understanding bank.

During training, the model learns how to calculate these vectors to make useful connections. When it writes, it uses those learned calculations.

The model performs several such weighings and repeats them through its layers. This drawing shows 1 weighing with invented weights and omits attention to the token itself. It has 21 pairs for 7 tokens and 91 for 14. These are connections in the drawing, not a count of billable token reads.

During generation, an inference cache usually reuses earlier attention states. Prompt caching across requests is a separate mechanism: a matching prefix can be billed at a lower rate, while new or uncached input uses its own rate. New tokens still depend on earlier context. Writing

The model generates one token at a time

The model scores possible next tokens using the context so far, and a token is selected. It joins the sequence and the next prediction uses that longer sequence. Typical decoding reuses cached states for earlier tokens instead of calculating the whole prefix from scratch each time.

The real cost

Output is priced above input in the table in the model unit. The model processes the input before decoding an answer token by token. Each new token requires another decoding step and depends on what came before it, with earlier states usually reused from a cache.
