Before anything reaches the model, your text is cut into chunks and every chunk is swapped for a number. Those chunks are tokens.

Tokens measure how much text fits and how much is processed. A token is usually a few characters rather than a whole word, so a token count is neither a word count nor a character count.

The exact split depends on the model and the language, so for context limits and cost estimates, use the token count your tool reports.

Images become tokens too, billed the same way. Claude counts roughly 1 token per block of 28 by 28 pixels, so a screenshot of 1000 by 1000 pixels is about 1,300 tokens. A larger image is scaled down first: on current models 1 image costs at most about 4,800 tokens.

Reading

Models do not process text as separate words

A tokeniser cuts text with a fixed vocabulary and rules learned from text: common words often stay whole, others split into pieces. Each tokeniser cuts differently, even between versions of one model. Claude Opus 5.5 cuts finer than Opus 4.6: the same text becomes about 30% more tokens, shorter on average.

In these examples, text and Java cost about the same per character, a log line nearly 2 times as much and an id nearly 3 times. The ratios vary with the text and the tokeniser. Long logs full of ids can fill the context quickly.

With this tokeniser the sentence above is 10 tokens in English and 12 in Dutch. Tokenisers learn their pieces mostly from English text, so most other languages need more tokens for the same content. They cost more and fill the context sooner, which says nothing about the quality of the answers.

Attention

In He deposits his money at the bank, bank could be a river bank or a financial institution. deposits and money point to the right meaning. To make such connections, the model weighs information from other tokens. That weighing is called attention.

For each token the model computes 3 vectors. The query is the question the current token asks: what am I looking for? The key is what every token says about itself: what am I relevant for? The value is the actual content: what do I pass on if you pick me?

For bank, the model compares its query with the key of every token before it and its own. The better they match, the more of that value counts: a lot of deposits and money, little of the. So bank here means a bank for money.

How to compute those vectors is learned in training. The KV cache further down keeps only keys and values: a query is only needed for the new token.

That step runs many times side by side and again in every layer, each time with new vectors. This drawing shows 1 run, with invented weights and without a token's attention to itself: 21 pairs for 7 tokens, 91 for 14.

Writing

The model generates 1 token at a time

The model scores every token in its vocabulary based on the text so far, and 1 is picked and appended, so the next prediction starts from a longer text. A token depends only on what comes before it, so appending changes nothing already calculated: the model reuses that work from a cache rather than redoing it. Across requests too, a request that starts with the same text as an earlier one can reuse that start at a lower rate That is prompt caching, and its rates close this unit.

After it alone, almost anything can follow, such as is or was. After the build failed because it, timed becomes the favourite. Everything you leave in front of a model changes what comes out of it, whether you meant it to or not.

The favourite does not always come out. The scores are probabilities and the model picks one according to them, so the same question asked 2 times can get 2 different answers. None of the other words above was impossible, only less likely.

You do not set any of these yourself: Claude Code and Copilot choose them for you, and the newest Claude models accept only the defaults.

The real cost

Output is priced above input in the table in the model unit. The model reads all input at once but writes 1 token at a time, 1 pass per token.

KV cache

The cache the model reuses while writing is the KV cache: the key and value of every token so far. Prompt caching keeps it for your next request. It sits in the GPU's memory, and for Llama 3 70B that is about 320 KB per token, or 32 GB for 1 conversation of 100,000 tokens. That cache and the model's weights are why AI data centres buy memory in bulk, and why RAM has become so expensive.

Prompt caching

On Anthropic’s API, a cache write costs 1.25 times input for a 5-minute cache or 2 times for a 1-hour one, and a cache read 0.1 times input or less, depending on the model. Copilot bills it too. Your harness and account decide the lifetime.

The cache only matches from the start, and each model has its own. So pick your model before you begin.
