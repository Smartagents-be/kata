Everything you send the agent is a prompt. Of everything a model is handed it is usually the smallest, and the session dwarfs it. It is also the most valuable, because it is the one part carrying your intent.

You rarely send just one. Some prompts are fresh queries you type. Others come back after the agent interviews you about the task.

Instruction

A prompt is an instruction, so say what you want the model to do. Every inaccuracy in it compounds once the agent starts work. Putting one right while it is already working is steering, which comes later.

Reasoning level

A prompt is seldom enough on its own to carry everything you meant by it. Models work the question over before they answer, and how much of that they do is the reasoning level. In Claude Code it runs from low up to xhigh. Turn it up and the model reflects on your question rather than answering it straight That absorbs some of the imprecision and the missing information, so what comes back is closer to what you actually meant.

The higher the reasoning, the more tokens the model spends thinking. Those tokens stay in the context and add to the cost The dial is a command in your harness rather than a line in your prompt, so you can move it per task. Turn it up for a vague ask, and down for one you have already made exact.

That thinking also covers the agent's own moves:, which file to open next and what to hand itself as input for the step after that.

Meta-prompting

Meta-prompting is letting a model write the prompt. You say roughly what you want, it writes the instruction, and you read it back and fix the parts it got wrong.

Spend an expensive model on this. Writing a prompt is a few hundred tokens next to executing one, so the top tier is cheap here Which tiers there are, and what they cost, is the unit on the model.

Plan mode

Plan mode is meta-prompting the provider already built for you. The agent interviews you about the task, hands back a plan, and waits. You edit it, ask for another pass, or approve it. No code is written until you do.

A cheaper model driven through a plan routinely beats a one-shot on the expensive one. Most people have that the other way round. The plan turned a vague ask into an exact instruction. What was missing was precision, not a bigger model.

It is not the move every time. A task you have already cut down to one file and one obvious change is a task whose decisions are made, and an interview about it hands them back to you as a document to approve. Ask for it straight instead .

One ask, not three

Ask for everything you want from one part of the application at once Every follow-up is another turn, and every turn adds noise the next turn has to read past. Three separate questions leave the window messier than one question covering all three.

Be exact

"Fix the login" and "make TitleController return a 404 when the catalogue comes back empty" go to the same model. The second names the class and the case. The first leaves the model to guess both.
