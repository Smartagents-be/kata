Good agentic projects start with good software engineering. That is the whole line between vibe coding and agentic engineering.

Vibe coding is asking for a feature, skimming what comes back, and running it. When it breaks you paste the error and say "fix this". That works for about an hour. Then the fixes start breaking each other. The loop feels productive right up to the moment you cannot answer a simple question about your own repository.

Software engineering has always been a craft. A problem arrives from the business, you break it down until each part is small enough to be sure about, and you pour the result into a process that runs as code. None of that changes when an agent does the typing.

Domain-driven design

Folders and classes carry the names the business uses. Headline is a headline and publishing/ is where publishing lives. Ask to change a headline and your sentence has already named the file

Clear domain names make instructions and searches more precise. Headline in your request points towards Headline in the tree. That helps the agent locate relevant code.

Vertical slices

A layered application invites you to build it a layer at a time: all of the data access, then all of the business logic, then the screens. Nothing runs end to end until the last layer is in, and that is the first time you learn whether the layers fit. Cut it the other way: 1 use case with everything it needs, from the screen down to the table, running before you start the next one. That is a vertical slice.

Put the slices that belong together in 1 module, and name it after what the business does. article-publishing/ holds the form, the endpoint, the rules and the table for publishing. Every slice is 1 turn of the feedback loop, and the module keeps that turn short, the way the unit on quality gates asks: mvn -pl article-publishing verify answers about the part you changed and nothing else.

Hexagonal architecture

Inside each module, the domain sits in the middle, the machinery lives behind adapters, and the direction of a call is a folder you can point at. No class outside adapter/ names Postgres or S3, so the code that talks to the database sits in 1 folder, and swapping it out starts there.

What that saves with an agent is the search. It opens application/ for a use case and adapter/outgoing/ for the thing that talks to S3, instead of reading half your repository into the context first .

The right words

Name the concept you want. “Put a repository in front of this JDBC call” specifies a design choice; “clean this up” leaves it open. Pattern names, layers and domain terms reduce guessing Review whether the chosen structure fits the actual problem.
