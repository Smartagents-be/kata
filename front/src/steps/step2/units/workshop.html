In this workshop you write none of the code. Not the tests, not the refactor, not the missing method, not the native build. You set the project up, you say what has to be true, and you read what came back. Everything else is the agent's.

Point your agent at exercises/step2/java: a library loans domain, ports and adapters, with a late-fee rule in the middle of it. It compiles, and the one test it ships with passes, so the default build is green. That makes it exactly the kind of code a quality gate exists for: one method too branchy to read, and almost no tests behind it.

Run the commands below from exercises/step2/java unless the block says otherwise, because each step of this kata is its own Maven project. Set an afternoon aside.

Pre-flight

Run the check before you change anything. It goes red. The rows it prints are your 3 goals with the numbers you are short of. Clear one and a flag in braces takes that number's place. The machine wrote your brief, so this page does not have to. 

cd exercises/step2/java
mvn verify -Pgraded

Then spend 10 minutes on the repository rather than the code, on what the setup unit had you go looking for. Hand those 10 minutes over as well. An agent that reads this project writes a better briefing for it than you will from memory.

1 goal, 3 flags

Hand the module over as an outcome with the check in it: 1 goal, no list of tests and no refactor plan. Then leave it alone, the way the unit on long-running goals and cost describes. This module is small, so the wait is minutes rather than the afternoon that unit priced. The sentence you hand over is the same sentence at any size. 

> Goal: `mvn verify -Pgraded` goes green in exercises/step2/java.
  Run it after every class you change, keep the default build
  green, and do not change a public signature.

If it comes back with a question instead of a diff, the rule you wrote in the pre-flight is doing its job.

1 of the 3 does not move when you add tests. When the other 2 are green and that number is still short, stop asking for tests and read what the row is measuring.

2 jobs, neither waits

The last 2 flags are independent, so run them at once. Give each one its own worktree. 2 Maven builds in 1 target/ fight over it. The 2 git lines are the exception to the rule above: run them from the repository root, and open a terminal there for each job. The second comes back while you are still reading the first. 

cd ../../..
git worktree add -b feat/statement ../kata-statement
git worktree add -b feat/native ../kata-native

In the first, the spec exists and it is failing. A tagged suite describes a method nobody wrote, and the endpoint behind it answers with a 500. Open plan mode against those tests, then check what it produces against the test names, one by one. Green tests, then call the endpoint. The code is in the response. 

cd ../kata-statement/exercises/step2/java
mvn test -Pchallenge
mvn spring-boot:run
curl localhost:8082/api/loans/statement/STUDENT

In the second, nothing is failing, because nothing has been built. Compile step 2 all the way down to a native executable. You need a GraalVM JDK for it, set as JAVA_HOME or GRAALVM_HOME, plus a C compiler toolchain and about 4 GB of free memory. Each attempt costs minutes, which makes this the worst place in the kata to guess, so plan it first. It compiles, it starts, and where the flag should be it prints a miss. Your plan was a piece short, and the image tells you which piece. 

cd ../kata-native/exercises/step2/java
mvn -Pnative native:compile
SERVER_PORT=8081 ./target/kata-agentic-java-step2

If a run stalls, cut the goal down. Take the one failing test, or the one line the image printed, and hand that back on its own.

The board

Each flag your run printed goes in the box beside its name, in English whichever language you are reading in.

Debrief

5 green rows say the code is right. They say nothing about how you got there, because a process leaves no exit code. Go and look.

That is the step. What is left has nothing to do with the agent. Step 3 is about what changes around the work when this is how the work gets done.
