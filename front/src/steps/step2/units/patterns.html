The third time you type the same instruction, stop typing it. A correction you repeat is not a prompt problem. It is a piece of knowledge with no home yet, so you carry it in by hand every session .

Lesson prose here kept coming back with em-dashes in it, and quizzes kept getting throwaway distractors. Both rules now live in .claude/skills/ as lesson-writing and quiz-writing, next to adding-a-step and repo-setup, which arrived the same way. They load with the task instead of after the mistake.

Give it a home

A convention goes in CLAUDE.md. A procedure with steps becomes a skill. Something that has to happen every time, whether or not anybody remembers, becomes a hook. The habit worth building is noticing the repetition at all.

Take one you have already explained three times. A new step in this kata needs a folder under front/src/steps/, one HTML file per unit, two locale files, an index.tsx exporting the step and a line in steps/index.ts. In CLAUDE.md that is a paragraph, read at the start of every session and paid for on every turn after it. As a skill it is a procedure, and it costs nothing until a task matches its description Better. Both are prose being interpreted, though, so the agent builds the folder by hand, slightly differently each time.

A script instead

Ask Claude to write the script, once: scripts/new-step.sh step3 creates the folder, both locale files, the unit stub and the registry line The skill shrinks to about three lines. Take the name, run the script, check what came out.

It wins for reasons that have nothing to do with agents. Same input, same output, no interpretation in between, so step 3 and step 7 come out identical rather than similar. Changing the convention is now a diff somebody reviews, instead of a sentence that quietly moved in a markdown file. And anybody can run it: the colleague who does not use an agent, the new hire on day one, the pipeline. A skill only helps the people who have Claude open.

Around the script

What stays in the skill is the judgement. Is this name valid, did the result hold together, and what do you do when it did not. When it has to run whether or not anybody asks, a hook calls the same script. The model no longer has to be right about your layout: it has to run one command and read the output, which is a far smaller thing to be right about.

Not everything reduces to a script, and forcing it helps nobody. The em-dash rule in lesson-writing is taste, and taste has no exit code. Its check is a grep, though, so even that one ends in something runnable. When you can name the check, script it. When you can only describe the taste, write it down and keep it short.
