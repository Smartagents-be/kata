The third time you type the same instruction, stop typing it. A correction you repeat is not a prompt problem. It is a piece of knowledge with no home yet.

Skill iteration

The first skill you write feels like magic. A writing skill is the easy one: a line about the voice you are after, and the correction you were tired of typing, in the file shape the setup unit drew. 

---
name: lesson-writing
description: Write or revise lesson text. Use whenever you add a unit or
  edit any student-facing prose.
---

Write like a colleague explaining something at a whiteboard.

- No em-dashes, anywhere. Two short sentences almost always read
  better than one long one.

The answers do get better. They also come back slightly off, and you find yourself repairing the same kind of sentence every time. Fix the output, by hand or with the agent, then hand it both versions and ask what the skill failed to say. Paste them into the prompt, or point it at the git diff. Write the answer back into the skill Do that a few rounds and it starts sounding like you. Here is that writing skill one pass later, one rule longer. 

---
name: lesson-writing
description: Write or revise lesson text. Use whenever you add a unit or
  edit any student-facing prose.
---

Write like a colleague explaining something at a whiteboard.

- No em-dashes, anywhere. Two short sentences almost always read
  better than one long one.
- Do not announce the count. "Two things matter here" tells the
  reader nothing they cannot see for themselves one comma later.
  Say the things and let there be two of them.

The corrections stop coming back. And a skill is a file in the repository rather than a habit in your head, so everyone on the team works from the same one without anybody explaining it.

Scripts

You may not write much Bash or Python. Your agent does. So when a repetition has an expected end result, scaffolding a domain or cleaning a database before a demo, a script is usually worth writing Then add a skill that calls it, or the agent will never know it is there.

A script is predictable. Same input, same output, no interpretation in between. When it does the wrong thing you change the script, with the agent if you like, and it stays changed for every run after that. The agent stops working the steps out again as well, so it spends neither tokens nor time on something you already know the answer to .
