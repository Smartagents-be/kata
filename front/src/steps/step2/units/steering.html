Mid-flight

Stop it with Esc in Claude Code, Ctrl+C in Copilot CLI or the Stop button in IntelliJ. While it is still thinking, nothing is on disk. Once it is writing files, you also decide what to revert. A rewind does not always undo what a shell command changed, so Git is still your undo.

Something small you type in while it works It keeps working until your sentence arrives, so for a wrong direction you stop it first. In IntelliJ, the Copilot agent holds your sentence until its current step is done, and Send Immediately sends it straight away. The Local agent cannot take one mid-run.

A new session is the heaviest move. You lose everything the run worked out, and also whatever sent it the wrong way.

Interrupt, or go back

A correction works: "Not that one, the rule lives in LateFeePolicy." But the wrong file stays in the context in full and is sent again on every turn The cache makes that cheap, not small. Every turn still to come is read against a file you did not want.

Go back to the message that sent it the wrong way and change it, and everything after it is dropped. Claude Code, Copilot CLI and IntelliJ all let you do that. As far as the model knows, the wrong turn never happened.

When the agent gets stuck

Sometimes it is not 1 wrong turn: after a few attempts it is still not what you wanted. The test fails the way it did before, or each fix undoes the last. It says it sees the problem now. It said that last time. Nothing is wrong enough to correct, so you wait another round. Every failed attempt stays in the context and becomes the strongest pattern, so it writes another one.

Going back does not help, because your request was fine. Start a new session and tell it what did not work and why (step 1's unit on the session). Change something too: paste the failing output in, name the approach it must not try again, or do the awkward step yourself. A 2nd attempt in a clean context beats a 5th in a dirty one.

Make it stop at the gap

When an agent hits something nobody decided, such as a currency the tests never name, it usually guesses and carries on. The code compiles and the tests stay green, so you see it at review, if you see it at all. You cannot know in advance where those gaps are, so put the rule in the CLAUDE.md the setup unit gave you. 

## Gaps

Never assume. When something you need is not decided anywhere in
the repository, stop and ask me. When I answer, record the decision
in a test or in this file, so it is decided from then on.

Stopping is the part that matters. An agent that writes its guess down and builds on it anyway has saved you nothing. What you get back is 1 short question instead of a diff full of guesses. Put your answer in a test, and it is decided from then on, in every new session too.
