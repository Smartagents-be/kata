Run it on your own machine

Feedback is fastest when the whole application runs on your own machine. Frontend, backend, the database in a container, with data in it that covers the everyday cases and the edge cases. Then you look at what your users look at, and a wrong column shows up as a wrong column instead of a field name in a response body. The agent writes the change in seconds, and your check on it has to keep up.

Give the agent the same setup: the running app, and the browser server as described in step 1's unit on tools. Now it checks its own work before handing it back. It opens the page, sees the wrong column and fixes it in the same pass .

T-shaped

An agent implements faster than you do, and it gets better at it with every release. What it asks of you moves up a level. Keep the specialism you have, and know enough of the contexts around it to follow what the agent produced, answer it, and judge whether it holds. The agent handles the detail for everyone alike, so knowing the detail is worth less than it was. Knowing what good software engineering looks like is not, and that is what the engineering unit argues.

Where the day goes

You are not typing the code any more, so count where the hours actually go. Most of them go on driving the system end to end and reading whether it did what you wanted. The steering unit covers what you do while a run is in flight. This is the other half, the part after it comes back, and it is most of your week.

The other part is thinking. Go through the implementation details, argue both sides of them, and come out with a design decision you could defend. A decision you did not make is one the agent made for you.
